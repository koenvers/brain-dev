Eerste week lokale LLM’s op een laptop

[Blog] 7 okt 2026 · 6 min · ai experiment

Een week lang alles lokaal gedaan wat normaal naar een API gaat: samenvatten, code uitleggen, kleine classificatieklusjes. Doel was niet snelheid maar inzicht — wat verlies je precies als je quantisatie toepast?

De setup

# model ophalen en server starten (llama.cpp)
llama-server -m models/qwen2.5-7b-instruct-q4_k_m.gguf \
  --host 127.0.0.1 --port 8080 --ctx-size 8192 -t 8

# groei meten terwijl er geladen wordt
watch -n1 'ps -o rss= -p $(pgrep llama-server)'

16 GB geheugen, geïntegreerde GPU, 8 threads. De praktische grens: een 7B-model in Q4_K_M (~4,5 GB) laat ruimte over voor een context van 8k. In Q8 (~8 GB) begint het te wisselen met de browser erbij en is de latency verdwenen — dat is de echte vloer, niet de geheugensom.

Wat ik meet

  • Q4_K_M — snelst, merkbare kwaliteitsdaling op redeneren; goed voor samenvatten en classificeren.
  • Q6_K — het midden dat ik voor code-uitleg gebruik.
  • Q8_0 — langzaam op mijn hardware, en het verschil tegenover Q6 was in mijn testen klein.

De kern van wat ik leerde zit in die laatste regel: de vorm van hoe je quantisatiet verschil uit — hemelsbreed tussen Q4 en Q6, nauwelijks tussen Q6 en Q8. Zonder de meting had ik Q8 als "veiligste keuze" genomen en elke dag tien seconden per prompt betaald.

Waar het schuurt

  • Geen streaming-dashboard: tokens/sec meten doe ik met --prompt-processing-stats of een simpele timer.
  • Tool-calling is firmware-afhankelijk; lokale servers ondersteunen niet elk schema dat een API wel begrijpt.
  • Kleinere modellen hallucineren bij lange instructies sneller — de systeemprompt moet kort en eenduidig zijn.
# nulmeting: hoeveel tokens/sec haal ik echt?
llama-cli -m models/qwen2.5-7b-instruct-q4_k_m.gguf \
  -p "Schrijf 200 woorden over broeikaskasmodellen." -n 256 -t 8 \
  2>&1 | grep -E "eval time|tokens per sec"

Conclusie voor nu

Lokaal is serieus bruikbaar voor tekstbewerking binnen een van tevoren afgebakende scope. Voor alles wat met actuele kennis of lange contexten te maken heeft blijft een API de betere keuze. De metingen staan in experiments/ in het repo, zodat ik over een half jaar het zelfde kan herhalen met een nieuw model.
